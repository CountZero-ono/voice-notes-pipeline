# Antigravity Agent Workspace Rules

You are Antigravity, a coding assistant. This workspace uses a file-based backlog system to queue work for AI agents.

## Workspace Behavior

1. **Backlog Scan on Startup**:
   - At the beginning of the workspace session, automatically scan the `backlog/` directory for any markdown files containing `status: pending` or the tag `#status/pending` in their frontmatter.
   - If any pending backlog notes are found, present them to the user immediately, prioritize them, and ask the user if you should implement them.
2. **Execution**:
   - Implement the requested features or fixes specified in the pending backlog notes.
   - Run tests or verify correctness of code changes.
3. **Closing/Completion**:
   - Once a task from a backlog note is fully implemented and verified, update its YAML frontmatter setting `status: completed` (and tag `#status/completed`).

## Core Interaction Rule (Carved in Stone)
- **EXPLAIN & ASK FIRST, THEN DO:** Always explain the issue/feature, pitch the implementation plan, and explicitly ask for user approval BEFORE modifying any files or running commands. You are the coordinator—never execute changes unprompted.

## Architecture & Operational Reference
- **Audio Ingestion & STT (Cascading Tiers):**
  - **Tier 1 (Primary):** Local `faster-whisper` (`large-v3-turbo` on CPU, 4 threads).
  - **Tier 2 (Cloud STT Failover):** Auto-failover to Groq Cloud Whisper (`whisper-large-v3-turbo`) via `GROQ_API_KEY` in `.env` for sub-second cloud transcription if local Whisper hangs or fails.
  - Signal WebSocket dispatches audio handling asynchronously to a `ThreadPoolExecutor`.
- **Note Processing & LLM Fallback (Cascading Tiers):**
  - **Tier 1 (Primary):** Local Qwen 35B MTP (`http://127.0.0.1:1235/v1/chat/completions`) running via `llama-qwen-mtp.service` with 2 slots (`-np 2`), unified KV cache, `enable_thinking: False`, and DRY sampling removed.
  - **Tier 2 (Cloud Failover):** Auto-failover to b.ai Cloud Qwen (`qwen3.8-flash`) via `~/.hermes/bai.env` for Qwen-native distillation while SER7 is powered off.
  - **Tier 3 (Emergency Cloud Fallback):** Auto-cascades to Vertex AI Gemini Flash if b.ai is unavailable or promo expires (reversible via `VOICE_CLOUD_FAILOVER=vertex`).
  - **Tier 4 (Dead-Letter Safety):** If all LLMs fail, raw Whisper transcripts are preserved directly into `Inbox/Life/` with `status: dead-letter` and `#dead-letter`.
- **Calendar & Task Sync:** Google Calendar (`gcal_credentials.json`) & Google Tasks (`token.json`) handle live schedule integration. Obsidian Markdown in the Vault is the sovereign, offline local source of truth (Radicale CalDAV decommissioned). Notes are marked `status: "synced"` after verified sync success.
- **Data Safety:** All note writes and state modifications use `PyYAML`, `FileLock`, and atomic `tmp -> os.replace` operations.
- **Gateway Evolution (v2.2.0 - Active):** Primary STT and LLM inference is routed through the 24/7 BAMA Unified Inference Gateway (`http://192.168.1.37:8090/v1`) on Jasper Lake (`virtsrv2` / LXC 107) with dynamic LAN probing and transparent local/cloud fallbacks, freeing the pipeline from direct hardware socket coupling. Note categorization and GCal/Tasks sync remain in this daemon.
- **24/7 Worker Containerization (v2.4.0 - Active):** Daemon containerized on Jasper Lake (`bama` LXC 107) as `voice-notes-worker` listening to `signal-cli-rest-api` via internal Docker network. Dual-layer storage: local container volume caching for Signal interactive commands (`approve`/`reject`), and direct REST API syncing (`seafile_sync.py`) to remote Seafile Obsidian Vault (`https://seafile.eyenology.net`).
- **Muse Reviewer Execution:** When calling `muse-reviewer`, auto-start `~/Project-Launchers/muse` in background if not already running.
